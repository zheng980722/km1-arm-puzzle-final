## 1. 系统架构

```
        ┌──────────────────┐
        │  同步示教器       │  6 路电位器 → 实时跟随
        │  (Arduino)        │  周期 50ms 全 6 路帧
        └────────┬─────────┘
                 │
        ┌────────┴─────────┐        UART 115200, 8N1, ASCII
        │  仿生手套         │────────────────────────────┐
        │  (Arduino+ADXL345)│  手势/姿态 → 事件触发帧      │
        └──────────────────┘                            │
                                                        ▼
        ┌──────────────────┐                 ┌──────────────────────┐
        │  OpenMV 视觉模块  │◀── 功能指令 ────│  机械臂控制板         │
        │  (UART3)          │── 舵机帧/状态 ─▶│  (Arduino, 解析+6PWM) │
        └──────────────────┘                 └──────────────────────┘
```

- **控制板**是唯一执行者：解析命令 → 输出 6 路 PWM 给舵机。
- 三个输入设备**地位对等**，都是"发命令的客户端"，协议同一套。
- OpenMV 双向：既接收功能指令，又回传舵机运动帧（视觉伺服）。

## 2. 物理层与链路层

| 项 | 值 | 依据 |
|---|---|---|
| 接口 | UART（TTL 串口） | 各 `.ino` `Serial.begin` |
| 波特率 | **115200 bps** | 示教器/手套 `Serial.begin(115200)`；OpenMV `UART(3,115200)` |
| 数据位 | 8 | OpenMV `bits=8` |
| 校验位 | 无（None） | OpenMV `parity=None` |
| 停止位 | 1 | OpenMV `stop=1` |
| 编码 | **ASCII 文本**（非二进制） | 全部 `sprintf` / 字符串 |
| 命令起始符 | **`$`**（上位机→控制板必须以此开头，控制器 serialEvent 用它重置接收缓冲区） | `y_uart.ino` serialEvent |
| 命令终止符 | `!`（触发命令完成标志 `uart_get_ok=1`） | `y_uart.ino` serialEvent |
| 多舵机帧定界 | `{` + **组号 `Gxxxx`** + 子帧序列 + `}` | 官方文档 §12 示例 |

**串口配置示例（任意 USB-TTL 调试）**：`115200 8-N-1`，无流控。

## 3. 帧语法总览

四类命令，按首字符区分：

| 起始符 | 类别 | 方向 | 示例 |
|---|---|---|---|
| `$#`（无 `{`） | 单舵机位置 | **上位机 → 控制板** | `$#005P1750T0500!` |
| `${` | 多舵机同步位置 | **上位机 → 控制板** | `${G0000#000P1500T1000!#001P1500T1000!}` |
| `$D` | 动作组 / 宏 | 上位机 → 控制板 | `$DGT:1-9,1!`、`$DST!` |
| `#`+功能名 | 视觉功能 | 控制板 → OpenMV | `#ColorSort!` |

> ⚠️ **上位机发命令必须以 `$` 开头！** 控制器 `serialEvent` 用 `$` 重置接收缓冲区。缺 `$` 则缓冲区不清零，垃圾数据拼接导致乱动。

形式化（BNF 风格）：

```
帧（上位机→控制板） ::= '$' 单舵机帧 | '$' 多舵机帧 | 动作组帧
单舵机帧   ::= '#' ID 'P' PWM 'T' TIME '!'
多舵机帧   ::= '{' 'G' GROUP 单舵机帧+ '}'
动作组帧   ::= "$DGT:" NUM '-' NUM ',' NUM '!'      (* 播放动作组 *)
             | "$DST!"  | "$DJJQ!"  | "$DJMS!"
视觉功能帧 ::= '#' FUNC '!'                          (* 控制板→OpenMV，上位机不用 *)
ID         ::= 3 位十进制 (000~254)
GROUP      ::= 4 位十进制 (动作组编号，默认 0000)
PWM        ::= 4 位十进制 (脉宽 µs，0500~2500)
TIME       ::= 4 位十进制 (运动时间 ms，0000~9999)
NUM        ::= 十进制整数
FUNC       ::= StartLed | StopLed | RunStop | ColorSort | ColorStack
             | FaceTrack | ColorTrack | ApriltagSort | ApriltagStack | ApriltagNumSort
```

## 4. 舵机位置指令（核心）

### 4.1 单舵机帧

```
#005P1750T0500!
│└┬┘│└──┬─┘└─┬─┘│
│ │  │  │    │  └─ '!'  结束符
│ │  │  │    └──── T    运动时间，4 位，单位 ms
│ │  │  └───────── 'T'  时间字段分隔符
│ │  └──────────── PWM  脉宽，4 位，单位 µs
│ └─────────────── ID   舵机编号，3 位
└───────────────── '#'  起始符（'P' 为脉宽分隔符）
```

#### 字段定义

| 字段 | 位宽 | 类型 | 范围 | 单位 | 说明 |
|---|---|---|---|---|---|
| `#` | 1 | 定界 | 固定 | — | 单帧起始符 |
| ID | 3 | 十进制 | `000`~`005` | — | 舵机编号，必须 3 位（前导 0 补齐） |
| `P` | 1 | 定界 | 固定 | — | 脉宽字段引导符 |
| PWM | 4 | 十进制 | 约 `0500`~`2500` | µs | PWM 高电平脉宽；`1500`=中位 |
| `T` | 1 | 定界 | 固定 | — | 时间字段引导符 |
| TIME | 4 | 十进制 | `0000`~`9999` | ms | 运动到位耗时；`0000`=立即/不限速 |
| `!` | 1 | 定界 | 固定 | — | 帧结束符 |

### 4.2 多舵机同步帧

上位机发送时：**`$` 开头** + `{` + **组号 `Gxxxx`** + 子帧序列 + `}`：

```
${G0000#000P1500T1100!#001P1500T1100!#002P1800T1100!#003P0860T1100!}
```

- `$` 帧起始符（控制器 serialEvent 用它重置缓冲区，**必须带**）
- `{` 多舵机定界开始
- `G0000` 动作组编号（4 位十进制，默认 `0000`）
- 中间为连续 `#...!` 子帧，无分隔符
- `}` 多舵机定界结束
- 各子帧 TIME 取相同值即同步到位

> ⚠️ **缺少 `$` 或 `Gxxxx` 会导致控制器解析失败，舵机乱动！**

内部模块（如 OpenMV 视觉伺服）直接发送时不带 `$` 前缀（`kinematics.py:94`），因为控制板内部解析路径不同。

### 4.3 角度 ↔ 脉宽换算

源自 `kinematics.py:88-91`，270° 量程、1500 为中心：

```
pwm   = 1500 ± 2000 × angle / 270
angle = (pwm - 1500) / 2000 × 270
```

| 角度 | 脉宽 |
|---|---|
| -135° | 500 |
| -90° | 833 |
| 0°（中位） | 1500 |
| +90° | 2167 |
| +135° | 2500 |

> 注：正负方向（`+`/`-`）各舵机不同，代码里部分舵机用 `1500-`、部分用 `1500+`，且示教器对 003/004 再做 `3000-pos` 反向。接线后以实测方向为准。

## 5. 舵机 ID 与脉宽范围

6 路（`DWQ_NUM 6`）。脉宽**工作范围**取自示教器映射表 `readDwqControlServo.ino`（这是实测安全行程，比 500~2500 硬件极限更窄）：

| ID | 功能（推断） | 工作脉宽范围 | 方向 | 依据 |
|---|---|---|---|---|
| 000 | 底座旋转（yaw） | 500 ~ 2500 | 正 | 手套左转 `P2400` / 右转 `P0600` |
| 001 | 大臂关节 | 1000 ~ 2000 | 正 | 后仰 `P2000` / 前倾 `P1140` |
| 002 | 小臂关节 | 700 ~ 2300 | **反**（2300→700） | 后仰 `P2000` / 前倾 `P1850` |
| 003 | 腕部 | 700 ~ 2250 | 发送时再反向（`3000-pos`） | 示教器映射 |
| 004 | 腕部 | 500 ~ 2500 | 发送时再反向（`3000-pos`） | 示教器映射 |
| 005 | **机械爪（夹爪）** | 800 ~ 1900 | **反**（1900→800） | 闭合 `P1750`/`P1700`，张开 `P1200`/`P1000` |

> 安全提示：超过工作范围可能堵转/损坏舵机。新设备先手动确认各轴极限。

## 6. 动作组 / 宏指令

控制板内置若干**动作组**（预编排的多舵机时序），由 `$D` 指令触发（`Ard代码V1.1.mix` 匹配 `$DGT`/`$DJJQ`/`$DJMS`）。

| 指令 | 格式 | 含义 | 示例 |
|---|---|---|---|
| 播放动作组 | `$DGT:<起>-<止>,<速度>!` | 播放编号区间内的动作组序列 | `$DGT:1-9,1!` |
| 停止 | `$DST!` | 停止当前运动 | `$DST!` |
| 宏指令 A | `$DJJQ!` | 控制器内部分支（语义见 §13） | `$DJJQ!` |
| 宏指令 B | `$DJMS!` | 控制器内部分支（语义见 §13） | `$DJMS!` |

**`$DGT` 字段定义**

| 字段 | 说明 |
|---|---|
| `<起>` | 起始动作组编号 |
| `<止>` | 结束动作组编号 |
| `<速度>` | 播放速度倍率（示例均为 `1`） |

**已知出现的动作组区间**（源码统计）：`1-4`、`1-9`、`10-19`、`20-29`、`30-38`。

**使用示例**：
```
$DGT:1-9,1!    → 以 1× 速度播放 1~9 号动作组（手套"模式键"触发，约 16s 一套）
$DGT:1-4,1!    → 播放 1~4 号动作组（视觉码垛流程中调用）
$DST!          → 立即停止（手套回到中立姿态时发送）
```

## 10. 完整使用示例

### 示例 1：示教器实时跟随（每 50ms 一帧，6 路全发，T=0000）

```
{#000P1500T0000!#001P1500T0000!#002P1500T0000!#003P1500T0000!#004P1500T0000!#005P1500T0000!}
```
含义：6 路舵机全部实时跟随电位器，无加减速（T=0000）。出处 `uart1_send.ino`（注意 003/004 用 `3000-pos`）。

### 示例 2：仿生手套手势

| 手势 | 发送帧 | 效果 |
|---|---|---|
| 握紧 | `#005P1750T0500!` | 机械爪闭合（0.5s） |
| 张开 | `#005P1200T0500!` | 机械爪张开（0.5s） |
| 右转 | `#000P0600T1500!` | 底座右转（1.5s） |
| 左转 | `#000P2400T1500!` | 底座左转（1.5s） |
| 后仰 | `{#001P2000T1000!#002P2000T1000!}` | 大臂+小臂后仰（1s，同步） |
| 前倾 | `{#001P1140T1000!#002P1850T1000!}` | 大臂+小臂前倾（1s，同步） |
| 回中 | `$DST!` | 停止 |
| 模式键 | `$DGT:1-9,1!` | 播放整套动作组 |

### 示例 3：视觉色块分拣一次完整动作序列（`colorSort.py`）

```
1. kinematics_move(0,100,70,1000)     → {#000P..T1000!#001P..T1000!#002P..T1000!#003P..T1000!}  移到搜索位
2. {#005P1000T1000!}                   → 张开爪
3. kinematics_move(x,y,70,1000)        → 移到色块上方
4. kinematics_move(x,y,30,1000)        → 下放到色块
5. {#005P1700T1000!}                   → 闭合爪夹取
6. kinematics_move(x,y,120,1000)       → 抬起
7. kinematics_move(100,60,120,1000)    → 转到目标框上方
8. kinematics_move(100,60,70,1000)     → 下放
9. {#005P1000T1000!}                   → 张开爪放下
10. kinematics_move(0,100,70,1000)     → 归位
```
其中 `kinematics_move(x,y,z,t)` 内部做逆运动学，输出 4 路（000~003）同步帧。

### 示例 4：上位机 / 串口助手测试（115200 8N1，**必须带 `$` 开头**）

```
$#005P1750T1000!      ← 夹爪闭合，1 秒到位
$#005P1200T1000!      ← 夹爪张开
$#000P0600T1500!      ← 底座右转
${G0000#000P1500T1000!#001P1500T1000!#002P1500T1000!#003P1500T1000!}   ← 4 轴回中位
$DGT:1-9,1!           ← 播放动作组
$DST!                 ← 紧急停止
```

> ⚠️ 示教器/手套/视觉模块的源码中**不带 `$`**，是因为它们和控制板共享同一条总线、控制器内部解析路径可能不同。上位机从外部发命令**必须加 `$`**，否则 serialEvent 缓冲区不重置，导致乱动。

## 11. 接收端解析参考实现

伪代码（控制板侧）：

```
on_line(line):
    line = trim(line)
    if line == "" : return
    if line[0] == '{':                      # 多舵机同步帧
        for each sub in split_inside_braces(line):   # 拆出每个 #...!
            parse_servo(sub)
    elif line[0] == '#':                     # 单舵机帧
        parse_servo(line)
    elif line.startswith("$DGT:"):           # 动作组
        body = line[5 : index('!')]          # "1-9,1"
        start, rest = split(body, '-')
        end, speed  = split(rest, ',')
        play_action_group(int(start), int(end), int(speed))
    elif line == "$DST!":   stop_motion()
    elif line == "$DJJQ!":  macro_jjq()
    elif line == "$DJMS!":  macro_jms()
    else:
        ignore()                              # 调试回显等

parse_servo(s):                               # s = "#005P1750T0500!"
    assert s[0] == '#' and s[-1] == '!'
    id  = int(s[1:4])                          # 005
    p   = s.index('P'); t = s.index('T')
    pwm  = int(s[p+1 : t])                     # 1750
    time = int(s[t+1 : -1])                    # 0500
    if id > 5 or pwm < 500 or pwm > 2500: clamp_or_drop()
    move_servo(id, pwm, time_ms=time)
```

## 12. 注意事项与边界

1. **ID / 脉宽必须定长**：ID 3 位、PWM 4 位、TIME 4 位，前导 0 不能省（`%04d`/`{:0>4d}`）。
2. **T=0000** 表示立即/不限速，示教器实时跟随用它；定位动作建议给足时间（如 1000）避免冲击。
3. **方向不一致**：002/005 映射反向，003/004 发送时 `3000-pos` 再反向；接线后实测方向。
4. **脉宽越界**会堵转/发热，限制在 §5 工作范围内。
5. **视觉功能帧（`#ColorSort!` 等）只由 OpenMV 解析**，控制板收到应忽略，勿混淆。
6. **多设备共总线**时会冲突——实际产品是"一拖一"（同一时刻只接一个输入设备）。
7. `$BEEP!` 是 OpenMV 让控制板发声，不是控制板发给 OpenMV。
